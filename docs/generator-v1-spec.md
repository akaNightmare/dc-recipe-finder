# Генератор попыток v1

Спецификация первой версии «умного» генератора для фиксированной базы (типично 2 предмета) и размера рецепта 6.

## Цели v1

- Исключать дополнения, уже проверенные с **той же базой** в завершённой попытке (SUCCESS/FAILED).
- Не предлагать дополнения, которые **полностью покрывают** уже известный успешный рецепт (как `cleanIngredientLists`).
- Упаковывать оставшийся пул в попытки: база + до `(recipe_size - base_count)` дополнений; последняя попытка может быть короче.
- **Группы**: в одной попытке не более одного ингредиента с одинаковым `IngredientGroup` (база учитывается).
- **Тиры**: маппинг `IngredientRarity` → tier 1–4; на дополнения действуют лимиты (см. ниже), с поэтапным ослаблением.

## Не входит в v1

- Глобальный запрет «любая известная тройка внутри шестерки».
- Оптимальное covering design / минимизация числа попыток.
- Автовыбор следующей базы.

## Модель данных

### `ingredient.group` (`IngredientGroup` enum, nullable)

Буквы **A–P** — слоты взаимоисключения (как в ТЗ «1 группа на предмет»). `NULL` — без группы.

### Тир (вычисляемый)

| Rarity     | Tier |
|------------|------|
| Common     | 1    |
| Uncommon   | 2    |
| Rare       | 2    |
| Epic       | 3    |
| Legendary  | 3    |
| UltraRare  | 4    |

### История для базы B

1. **U(B)** — множество `ingredient_id`, которые встречались как **дополнение** (не база) в `RecipeListRecipe`, у которых есть связанный `Recipe` со статусом SUCCESS или FAILED, и база списка совпадает с B (по множеству id базы).
2. Для regenerate/create также учитываются **текущие** отмеченные строки того же `recipe_list_id`.

## Правила дополнений в одной попытке

Пусть `k = recipe_size - |base|`, `additions` — выбранные дополнения.

### Тиры (строгий режим)

- Не более 1× tier 2, 1× tier 3, 1× tier 4 среди дополнений.
- Суммарно tier 2–4: не более 2.

### Группы (строгий режим)

- Множество `{ group_id предметов в base ∪ additions }` без дубликатов (игнорировать `NULL` group).

### Ослабление при упаковке

Для каждой новой попытки перебор режимов:

1. strict (группы + тиры)
2. relax_groups
3. relax_tiers
4. relax_all

## Алгоритм упаковки

1. Собрать кандидатов из allow-листов минус ban, minus base, minus U(B), minus «успех-подмножество» (clean).
2. Жадно формировать попытки: в strict→relax_all выбрать до `k` дополнений (shuffle порядка кандидатов для разнообразия).
3. Использованные в попытке дополнения **не повторяются** в следующих попытках того же прогона.
4. Если в режиме strict не набирается ни одного дополнения — перейти к следующему режиму; если после relax_all пусто — остановить.

## API / код

- `generateAttemptsV1(...)` в `generate-recipes.helpers.ts` — новая функция; `generateRecipes` делегирует в v1 при `recipe_size` и размере базы, совместимых с v1 (base ≤ recipe_size, freeSlots ≥ 0).
- Create / Regenerate use cases без изменения контракта GraphQL.

## Тесты

Unit-тесты на: U(B), tier limits, group conflict, упаковку нескольких попыток, ослабление.
